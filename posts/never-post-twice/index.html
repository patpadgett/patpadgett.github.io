Never post twice. Yes, even when I run the damned thing twice.

grime95.com posts daily fiction to a website, Facebook and Instagram. Posting was easy. Keeping a retry from posting the same damned thing again took some work.

You want a script that posts something once a day, forty lines should do it. Then you get to spend the next week figuring out what happens when those forty lines half-work.

I run grime95.com[1], a serialized fiction site publishing one fictional small-town booking record every day at noon Eastern. Each goes to a static site (a GitHub Pages[2] repo), a Facebook Page, and Instagram. Cron[3] does it. Twenty percent of that script took eighty percent of the thought, most of it about what could go wrong.

My billing mediation habit kicks in here, because I've spent a lot of time reconciling things and I want a ledger I can check. I used SQLite[4], one row per (entry, channel). Status: pending | success | uncertain.

Three statuses, because sometimes I genuinely don't know what happened.

When a POST to Meta's Graph API[5] throws, you don't know whether the post exists. Maybe it completed and the response disappeared. Maybe the token expired and nothing happened. Instagram takes two calls, create a container and publish it, so it can half-happen. A leftover container expires on its own, but isn't easily distinguished from one that published.

POSTs get exactly ONE attempt. An exception marks the row uncertain, and the script stops touching that (entry, channel) pair. On the next run, GETs retry freely. Reading is idempotent, so I can keep looking without posting another copy.

Every channel adapter gets a checkpoint callback. The instant it has a remote ID, it calls that callback.

Verification can fail. The process can get killed. The ledger already knows a post with that ID exists, so the next run sees remote_id and doesn't repost. Instagram checkpoints even the container ID as container:<id> before publishing. Half-done counts as something I want written down!!

About 480 lines of Python. Standard library plus Pillow[6] for image checks. I wrote it in an afternoon and I'm proud of the thing. Getting the failure states right took the week after.

I don't want to babysit it every day at noon.
